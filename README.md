# doc-to-deck-py

Upload a Markdown or PDF file and get back a flashcard deck generated by Gemini or Claude, with its quality measured and its cost tracked.

This is a hands-on kata: a standalone Python rebuild of the AI document pipeline inside
[AnkiX](https://ankix.tech), built one layer at a time so every stage can be explained and defended.
A .NET version of the first two layers lives in [doc-to-deck-pipeline](https://github.com/maleek004/doc-to-deck-pipeline).

## What it does

1. **Ingest**: parses Markdown and PDF into an outline of sections (headings, code-fence aware,
   repeated PDF headers, footers and page numbers removed), with size, page and file-signature checks.
2. **Plan → generate**: asks an LLM to group the sections into modules, then to write atomic flashcards
   under a strict JSON schema. Gemini (hand-written REST client with its own retries) or Claude (official
   Anthropic SDK), picked per request. Every card goes through a rule-based quality gate.
3. **Evals**: a golden set of documents, rule-based metrics and a calibrated LLM judge, used to compare
   prompts and providers on quality, cost and latency.
4. **Cost and guardrails**: every LLM call logged with tokens and cost, a daily spend cap, and an atomic
   credit deduction that charges only when a call succeeds.

## Stack

Python 3.12+, uv, FastAPI, Pydantic v2, pdfplumber, httpx, the `anthropic` SDK, SQLite, pytest, ruff,
and one unstyled `index.html` in plain JavaScript. No LangChain: every stage is hand-built.

## Run it

```bash
uv sync
cp .env.example .env        # fill in keys, or leave them empty to use the fake provider
uv run doctodeck            # http://localhost:8000
uv run pytest
```

Tests never call a real provider and need no keys.
